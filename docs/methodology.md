# RE:Agent V1.0｜方法論定稿

## 定位

RE:Agent 是 AI to Agent 時代的學習與開發方法。從既有軟體、App、GitHub 專案、工作流程或企業系統出發，理解它如何完成工作，再沿用成熟能力，重新組合成能完成任務的 Agent。

## 四個核心動作

- **Reverse 看懂**：理解輸入、步驟、判斷與產出，拆行為，不拆程式碼。
- **Reuse 沿用**：盤點可使用的流程、資料、Skills、MCP、Tools、API 與開源套件。
- **Rebuild 重組**：安排新的任務分工，保留適用的成熟能力。重組不等於重寫。
- **Agent 執行**：理解、判斷、選擇、執行、檢查、修正，直到符合完成條件。

## STEP 01｜看

問：它原本在幫誰解決什麼問題？

做：選一件自己用過、輸入輸出看得見、一次能完成的工作。

留：原本工作說明。

完成標準：60 秒內能向別人說清楚這件工作，範圍是一件工作。

## STEP 02｜拆

問：收到什麼？做了什麼？如何判斷？交付什麼？

做：用 VAD 整理「輸入 → 步驟 → 判斷 → 產出」。

留：VAD 舊工作拆解圖。

完成標準：沒用過原系統的人，也能看圖說明工作如何完成。

## STEP 03｜定

問：Agent 到底要完成什麼？

做：用 VAC 說清楚輸入、任務、可使用能力、限制、產出、完成條件。

留：VAC Agent 任務卡。

完成標準：任務範圍與驗收條件明確，能用於第六步檢查。

## STEP 04｜找

問：這個能力是否已經有人做好？

做：盤點 Skills、MCP、Tools、API、開源套件，逐項決定沿用、找現成或自己做。沿用前確認適用性與使用條件。

留：沿用清單。

完成標準：每項能力都有明確決定。自己做只補真正缺少的部分。

## STEP 05｜組

問：哪些工作需要 Agent？哪些交給成熟工具？

做：Agent 負責理解、判斷、選擇、處理例外與修正；成熟工具負責固定、明確、穩定、可重複執行的工作。

留：新 Agent 工作圖。

完成標準：每項工作有負責者，並能說明分工理由。

## STEP 06｜驗

問：真的完成任務了嗎？

做：依 STEP 03 設定的完成條件檢查實際結果。

- 任務是否真的完成？
- 結果是否正確？
- 工具是否正確使用？
- 是否遵守 VAC 限制？
- 結果是否可以檢查與驗證？

留：執行結果與驗收判定。

符合條件為 PASS；不符合為 FAIL，回到出錯步驟修正，再驗收。回答完成不等於任務完成。

## 三個核心原則

1. 不要從零開始。
2. 不要全部重寫。
3. 不要為了 Agent 而 Agent。

## 關係與邊界

RE:Agent 是路徑；VAD 幫助看懂舊方法；VAC 定義新任務；現成能力提供執行手段；驗收確認任務結果。本版只介紹方法論，不收錄實測案例，也不以此文件宣稱新的實測已完成。

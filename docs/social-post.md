# RE:Agent｜AI to Agent 舊架構新 Agent 學習法

**從已經被驗證的智慧開始，讓 AI 真正完成工作。**

當我們想用 AI 改善一件工作，經常會直接問：「能不能幫我做一個 Agent？」

但在開始之前，有一個更值得思考的問題：

**這件工作，原本是怎麼被完成的？**

我們每天使用的軟體、App、試算表與企業流程，往往已經累積許多解決問題的智慧。輸入哪些資料、先做哪個步驟、遇到什麼情況需要判斷，以及最後應該交付什麼，都值得重新理解。

進入 AI to Agent 時代，這些經驗仍然有價值。真正需要學習的，是看懂既有方法，找出可以沿用的能力，再安排 Agent 與工具的分工。

這就是 **RE:Agent** 的出發點。

**一套方法，四個核心動作**

RE:Agent 將學習與開發路徑整理為：

**Reverse 看懂 → Reuse 沿用 → Rebuild 重組 → Agent 執行**

Reverse，是理解原本的方法如何解決問題。
Reuse，是找出已經存在、適合繼續使用的能力。
Rebuild，是依照新的任務需求重新安排分工。
Agent，則是運用這些能力執行工作，檢查結果，必要時修正。

可以把它想成重新整理一間廚房：先看懂料理流程，再盤點現有設備，安排每個人的工作，最後確認料理是否真的完成。

設備好用就保留，流程不順就調整，需要判斷的地方才安排判斷能力。

**重組，不等於全部重寫。**

為了讓這套方法能直接用於學習與工作，RE:Agent 將操作固定為六步：

**看 → 拆 → 定 → 找 → 組 → 驗**

**STEP 01｜看：先選一件工作**

第一步，先問：「它原本在幫誰解決什麼問題？」

選題可以掌握三個條件：**自己用過、輸入輸出看得見、一次能完成。**

範圍越清楚，越容易理解與驗收。如果一開始就想改造整間公司，很容易把不同問題混在一起，最後連成功的標準都說不清楚。

這一步要留下的是「原本工作說明」：誰使用？需要什麼？最後完成什麼？

完成標準很簡單：**能不能在 60 秒內，向別人說清楚這件工作？**

說不清楚，就先縮小範圍。

**STEP 02｜拆：用 VAD 看懂舊方法**

選好工作之後，接著理解它怎麼完成。

VAD 在這裡負責把工作畫清楚，依序拆成：

**輸入 → 步驟 → 判斷 → 產出**

收到什麼資料？經過哪些操作？在哪裡需要決定下一步？最後留下什麼結果？

這一步的原則是：**拆行為，不拆程式碼。**

即使不懂程式，也能觀察一件工作如何運作。重點是辨認其中的順序、條件與判斷，而不是先研究底層技術。

留下「VAD 舊工作拆解圖」之後，可以請一位沒用過原系統的人看看。如果對方也能說出工作如何完成，就表示拆解已經足夠清楚。

**STEP 03｜定：用 VAC 說清楚新任務**

看懂舊方法之後，才能決定希望 Agent 接手什麼。

這一步使用 VAC，把期待轉成明確的任務規格，至少說清楚六件事：

**輸入、任務、可使用能力、限制、產出、完成條件。**

要提供哪些資料？Agent 要做到哪裡？可以使用哪些工具？哪些事情不能做？最後交付什麼？如何判定成功？

「幫我處理好」是一個期待，但還不夠讓工作穩定執行。

越能具體描述完成條件，越容易檢查 Agent 的結果，也越容易在出錯時找到原因。

**VAD 把舊方法看懂；VAC 把新任務說清楚。**

兩者各自負責一件事，前後銜接。

**STEP 04｜找：沿用現成能力**

任務定義清楚後，先問：「需要的能力，是否已經有人做好？」

可以盤點的資源包含 Skills、MCP、Tools、API 與開源套件。

不必一次學會所有名詞。先理解它們分別可能提供操作規則、工具連接或實際執行能力，再依任務挑選。

每項需求只做三種決定：

**沿用：既有能力已經適合。**
**找現成：尋找可以直接使用的解法。**
**自己做：補上真正缺少的部分。**

這一步要留下「沿用清單」，讓每項能力都有明確去向。

判斷重點是是否適合任務、能否可靠使用，以及後續維護是否合理。工具數量多，不代表任務完成得更好。

**能沿用就沿用，把力氣花在真正需要改變的地方。**

**STEP 05｜組：重新安排誰負責什麼**

找到能力後，開始安排新的工作方式。

Agent 適合負責理解需求、判斷情況、選擇工具、處理例外與修正。

成熟工具則負責固定、明確、穩定、可重複執行的工作。

關鍵問題是：**這個環節真的需要判斷嗎？原本的工具是否已經做得很好？**

需要理解的地方交給 Agent，規則明確的地方保留成熟工具，才能讓分工更清楚。

這一步留下「新 Agent 工作圖」，說明每一項工作由誰負責、如何銜接，以及為什麼這樣安排。

**不要為了 Agent 而 Agent。**

真正有價值的重組，是讓工作更容易完成，也更容易檢查。

**STEP 06｜驗：真的完成任務了嗎？**

最後，回到第三步設定的完成條件，檢查實際執行結果。

至少問五個問題：

任務是否真的完成？
結果是否正確？
工具是否正確使用？
是否遵守 VAC 的限制？
結果是否可以被檢查與驗證？

符合條件，才判定 PASS；不符合，就判定 FAIL，回到出錯的步驟修正，再次驗收。

**回答完成，不等於任務完成。**

Agent 說「已完成」只是回覆。真正的完成，要有可以檢查的結果。這也是從聊天走向工作執行時，最重要的觀念轉換。

**六步走完，留下六項成果**

原本工作說明、VAD 舊工作拆解圖、VAC 任務卡、沿用清單、新 Agent 工作圖，以及執行結果與驗收判定。

這些成果讓想法變得具體，也讓討論有共同依據。公開教學可以逐步理解，課程學習可以依序操作，企業團隊則可以據此確認需求與責任。

RE:Agent 的核心，始終只有三個原則：

**不要從零開始。**
**不要全部重寫。**
**不要為了 Agent 而 Agent。**

當你準備開始下一個 AI 任務，先選一件熟悉的工作，問自己：

**我看懂原本的方法了嗎？知道哪些可以沿用了嗎？能清楚說明怎樣才算完成嗎？**

從這三個問題開始，讓舊智慧成為新能力，讓 AI 從回答問題，走向完成工作。
